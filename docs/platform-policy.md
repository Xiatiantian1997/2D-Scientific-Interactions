# 平台方法

目标是让读者通过操作理解一个关系。先保证直观与科学含义清楚，再处理外观；简化与夸张应服务理解，并说明模型边界。

## 一个实验模块包含什么

实验模块共同定义科学模型、图形表示和操作行为：画什么、能改什么、哪些量跟着变、怎样观察和比较。

在此之上，基础 UI 统一排版、字号、控件外观与反馈；主题再调整颜色、材质和装饰。换肤不能改变计算关系、图形含义或操作结果。

## 设计顺序

1. **确定理解目标。** 用一句话说明读者操作后应看懂什么，找出最容易误解的地方。
2. **确定模型。** 写明假设、单位、适用范围；区分可控输入、固定条件、派生结果和纯观察操作。公式能代数变形，不代表每个量都能独立调节。
3. **选择表示。** 从[模板目录](../templates/README.md)选合适方法。先让关键变化清楚，再增加必要细节；二维能讲清时，不为装饰增加空间复杂度。
4. **定义视觉含义。** 颜色、线、点、透明度各有明确职责。同一对象跨状态保持身份；辅助标记不能看起来像新的物理对象。
5. **定义操作与比较。** 操作尽量作用于对象本身，相关控件集中。比较保留尺度、视角及无关条件；动画说明物理过程还是状态切换，不能暗示不存在的因果。
6. **验证并接入。** 检查模型、状态转换、触摸行为与多实例隔离，再应用 UI 和主题。验证范围见[验证说明](validation.md)。

## 规则的边界

| 层级 | 内容 |
|---|---|
| 必须保持 | 科学约束、单位、稳定的视觉含义、公平比较、可读性、如实说明验证范围 |
| 默认采用 | 控件集中图下、操作区空白短按复位、固定播放槽位、默认静止、适合触屏的字号与命中范围 |
| 按需要调整 | 配色、圆角、材质、布局、视图数量、绘制技术与模型组合 |

默认规则遇到冲突时，以当前教学任务为准：例如画布空白用于放置粒子，就不能同时承担复位。说明替代操作即可，不需要为普通样式调整增加审批流程。

## 多模型与多视图

- **独立模型同页：** 各自保存状态、播放和复位范围。
- **同一模型的多个表示：** 共用状态，联动刷新；标清各图坐标，避免把位置、波数、能量混为同一空间。
- **物理耦合模型：** 明确接口、单位、因果方向、时间尺度与更新顺序；反馈关系需要合适的联立或迭代计算，不能只把同名变量相连。
- **模型或近似对照：** 使用共同输入和边界条件，说明差异来自哪里。

当前打包器提供隔离显示，不会自动建立模型耦合。需要联动时，在实验模块内实现共享控制器或明确的适配接口。

## 扩展方法

模板是参考，不是题目白名单。已有方法能表达的内容直接改编或组合；确实无法表达时，简要记录：

- 新的理解目标，以及已有方法缺少什么。
- 新表示与操作的含义，哪些默认规则需要调整。
- 科学依据、比较基准与验证方式。

验证有效后再纳入模板。用例用于检验平台，不必为每个知识点新建一套规则。
